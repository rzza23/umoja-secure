# artifacts/

Build-artifact snapshots for review. Not source code.

Tracked files are refreshed only when the underlying lockfile changes.
Spurious refresh noise defeats the purpose of having a git history of
these files.

## dep-tree.json

Generated by:
  cd backend && python3 ../scripts/ci/regen-dep-tree.py

The tree carries a `_meta` block with:
  - lockfile_sha: sha256 of backend/package-lock.json at generation time
  - schema: "umoja-dep-tree.v1"
  - generated_at_utc: ISO 8601 timestamp
  - generated_by: "scripts/ci/regen-dep-tree.py"

check-dep-tree-refresh.py verifies _meta.lockfile_sha against the
current lockfile. Regenerate whenever backend/package-lock.json
changes; the hash check catches a lockfile update without a
corresponding regen.

The tree uses `npm ls --omit=optional` internally so that optional,
os-constrained deps (fsevents on macOS, per-platform esbuild binaries)
don't appear. Those deps legitimately differ by platform. §11
enforcement (no Google runtime packages) is handled by the SBOM check
(check-prohibited.py), which includes optional deps for absolute
enforcement.

Per Build Master section 6, every PR should include a fresh
dep-tree.json reviewed for:
  - @google/*, com.google.*, googleapis, gaxios,
    google-auth-library, firebase*, tink (runtime deps only)
  - Any package without a resolved version
  - Any package newly added in the PR

Refresh this file when backend/package-lock.json changes. Do not
refresh on every `npm install` if the lockfile is unchanged -- the
dep-tree is deterministic for a fixed lockfile.

## What does NOT belong here

- sbom.json -- gitignored in both repo-root and backend/ .gitignore;
  generated on demand for review, not committed
- Any file that contains credentials, tokens, or environment-specific
  paths
- Build outputs (dist/, build/, node_modules/) -- gitignored by
  convention
